# PRD — DeepSeek Thread Deck

## 1. 背景与问题

用户在 DeepSeek 网页版每天开大量新对话，覆盖多个领域，但官方仅提供按时间的平铺列表，导致：

1. 对话无法按项目/话题分类，几百条后极难管理。
2. 同一项目反复开新对话，每次都要重复交代背景、上传文件。
3. 想探索不同路径时无法分叉，切换成本高。
4. 找不到以前问过的问题，重复提问。

本项目在不改变 DeepSeek 免费使用方式的前提下解决上述四类摩擦。

## 2. 产品边界

### 做

- 项目/文件夹/标签分类与侧边栏项目树。
- 本地全文检索（标题、正文、思维链），搜索命中跳回原对话。
- 新对话前相似历史提示。
- 项目级背景预设、文件清单、历史结论，一键注入新对话。
- 任意消息处的客户端分叉（重放模拟），原会话不受影响。
- 收藏、JSON/Markdown 导出。

### 不做

- 不接入 DeepSeek 开放 API，不要求 API Key，不产生 API 费用。
- 不替代网页版，不提供模型服务。
- MVP 不做云同步、MCP/Agent 工作台、多人协作。
- 不承诺服务端语义分叉；分叉是客户端重放，附件无法完整恢复，必须在 UI 明示。
- 不把插件做成重型工作台，主动回避 deepseek-pp 级复杂度。

## 3. 功能需求与验收

### P0 — 只读安全模式（0.1）

- 同步对话列表与消息到本地 IndexedDB。
- 项目/文件夹/标签分类，侧边栏项目树渲染。
- 标题/正文全文检索；收藏；JSON/Markdown 导出；命中跳回原对话。
- 验收：
  - 500 条对话、5 万条消息可完成同步。
  - 搜索 P95 < 300ms。
  - 网络面板确认无外传请求。
  - DeepSeek 改版导致读取失败时，UI 显示“同步不可用”但不崩溃。

### P1 — 上下文复用（0.2）

- 每个项目绑定系统提示词预设、文件清单、历史结论摘要。
- 新对话一键注入；支持模板变量（如 `{{project}}`、`{{date}}`）。
- driver 不可用时降级为复制到剪贴板。
- 验收：注入 < 2s；同一会话不重复注入；失败有明确提示与重试入口。

### P2 — 客户端分叉 + 相似提醒（0.3）

- 任意消息处“分叉”：读取该轮之前历史，创建新会话并按序重放，原会话不变。
- 附件缺失必须提示；失败可重试、可取消；分叉关系可查看。
- 发送前用本地 BM25/关键词检索相似历史，超阈值提示“你曾在 [项目 X] 讨论过类似问题，当时结论是……”。
- 验收：20 轮对话分叉成功且原会话消息数不变；driver 失效时只读功能正常；相似提醒误报率可接受，阈值可配置。

## 4. 数据模型（摘要）

以 `src/core/db/schema.ts` 为唯一事实源。

- `Project`：id、name、color、preset、fileRefs、summary、createdAt、updatedAt。
- `Conversation`：remoteId、title、createdAt、updatedAt、projectId、tags。
- `Message`：convId、id、role、content、thinking、order、attachmentMeta。
- `Fork`：parentConvId、parentMessageId、newConvId、status、createdAt。
- `SearchIndex`：convId、messageId、title、body、tokens。

`attachmentMeta` 仅存元数据；分叉重放不可恢复附件内容。

## 5. 降级与容错

| 失败场景 | 降级行为 |
|---|---|
| driver 不可用 / token 拦截失败 | 写入功能关闭，退回只读；注入改为复制到剪贴板 |
| IndexedDB 读取失败 | 保留上次缓存，提示“同步不可用” |
| 全文检索初始化失败 | 退回标题搜索 |
| 分叉中途失败 | 保留草稿与新会话链接，提示可重试 |
| DeepSeek 页面 DOM 改版 | 显示“适配中”，不阻塞只读功能 |

## 6. 成功指标

- P0：同步成功率、搜索 P95、零外传请求、崩溃率。
- P1：注入耗时、重复注入拦截率、降级触发率。
- P2：分叉成功率、原会话不变校验、相似提醒采纳率与误报率。

## 7. 主要风险

- DeepSeek 页面 DOM/存储结构改版：选择器集中管理，只读功能可降级。
- 中文分词效果不足：先 `Intl.Segmenter`，不足再评估 `segmentit`。
- 分叉附件不可恢复：UI 明示，避免用户误解。
- 扩展权限与商店审核：manifest 权限变更必须人工确认。
